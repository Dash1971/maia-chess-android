# Mobile Maia 2.3.0

Release-source preparation for **2.3.0+80**, promoted from Preview
**2.3.0-beta.7** (`c0b493e`). This document is not publication approval.
No 2.3.0 tag, signed APK or release is created by this promotion PR.

## What's new

- **Ten interface languages:** English, Japanese, Simplified Chinese, Korean,
  Spanish, German, French, Russian, Hindi and Brazilian Portuguese. Follow the
  device language or choose in Settings; selections survive restarts. PGN
  notation and saved game facts remain canonical. Translation review and
  terminology tracking are retained in `docs/l10n_review.csv` and the language
  review documents; native-language feedback remains welcome.
- **Recent Games preserves played dates and order:** viewing or analysing a
  record no longer moves its date to today or bumps it to the top. Older records
  without a reliable date remain explicitly unknown rather than inventing one.
- **Subtle result colors:** green for your win, red for your loss, amber for a
  draw, muted blue for incomplete; only the result text changes. Ambiguous
  results stay neutral, and screen readers receive player-relative descriptions.
- **Lichess-style quick controls:** 1+0, 2+1, 3+0, 3+2, 5+0, 5+3, 10+0, 10+5,
  15+10, 30+0 and 30+20, plus Unlimited and Custom. Available on Home and in
  Continue from here without changing the meaning of existing saved presets.
- **Faster optional human timing for short controls:** 1+0 targets average about
  one second (cap 3 seconds); 2+1, 3+0 and 3+2 average about 1.5 seconds (cap 4.5).
  Longer presets retain the original roughly two-second average and nine-second
  maximum. Inference counts toward the target; these caps do not limit actual
  computation time. General low-clock adaptation remains future work.

## Preserved behavior

Stable keeps its existing package `com.dash1971.maia_chess`, blue icon, signing
identity, 79M model, universal ABI output and offline permissions. Preview/Dev
flavors and the 5M development model are not promoted. Existing games, settings,
model hashes and engine versions remain intact. No W–L–D totals, estimated Elo,
or new human-timing setting is included.

The only newly required runtime packages relative to Stable 2.2.2 are Flutter's
SDK localization library and `intl` 0.20.3, already tested in Preview. Existing
runtime/toolchain dependency versions remain pinned; see the
[upstream/security review](../dependency-audit-2026-10-06.md) for checked updates,
coverage limits and deferral decisions.

## Release safeguards

The Checks workflow now includes a dependency advisory job. The combined
publication gate requires `test`, `dependencies` and `android` jobs to pass for
the exact frozen source. Network failures or incomplete dependency resolution
cannot become a clean audit. Fastlane description/changelog/screenshots are
updated in the source before tagging.

F-Droid qualification remains required after the source is frozen: inherit the
current canonical recipe, scan/build independently on Linux, compare unsigned
APKs, verify signing/alignment and the public developer binary, and observe
update detection and store publication separately. The review recipe contains
a proposed `v2.3.0` entry; qualification evidence must replace that with the
actual frozen full SHA. Do not create the tag merely to make a build work.

## Still required before publication

- Freeze the merged full source SHA and rerun the manual test/dependency/Android
  workflow against it; promotion checks do not qualify a later merge commit.
- Independently reproduce that exact source with the canonical F-Droid recipe
  on Linux, including source/binary scans and comparison to GitHub's unsigned APK.
- Complete upgrade and device checks for the final APK (including language
  switching, existing saved games/preferences and native engines).
- Sign only the verified artifact, run `tool/qualify_release.py`, and retain
  sanitized evidence. Publish only on the maintainer's explicit instruction.

The [release procedure](../RELEASING.md) remains authoritative.
