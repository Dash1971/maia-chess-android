# Independent source and first-snapshot audit

Read-only review of `strength/run_matches.py`, `app_rules.py`, `mobile_policy.py`, `PROTOCOL.md`, `analyze_results.py`, `verify_results.py`, preflight evidence and the app's installed `chess` 0.8.1 source. No model inference or edits to running harnesses were made.

No material correctness defect found:

- The sole primary contrast and fixed 1,200-game target precede outcomes. Six shards each generate exactly 200 games; alternating colors give 600 per policy color overall. Execution does not stop based on results.
- Each game and color has a distinct seed in the 6,000,000,000 range. Independent RNG objects are recreated per game and color; scheduling, cache reuse and prior games cannot consume a later game's stream. IDs encode shard and game number. All six current manifests agree with executed sources, T1/P.95 versus T1/P1, the intended pinned 79M model, 1600/1600 inputs, one ORT thread, standard initial position and no book/search.
- The portable policy is byte-identical to the previously audited helper. Its cache key includes every model input (piece placement, turn and conditioning levels); legal masking is reapplied from the live board, so omitted castling/en-passant/history fields in the model encoder do not cause reuse of the wrong legal distribution.
- The natural endpoint reproduces the installed app's actual 100-halfmove and three-occurrence raw-FEN rules. Raw en-passant is intentionally retained in the repetition key. Dart checks the whole historical sequence for any third occurrence. Checkmate wins result priority. These are app conventions, not prospective FIDE draw claims. Insufficient-material branches were separately translated directly from Dart for the independent replay.
- Durable JSON records determine completed games; a running game can temporarily have a PGN before its JSON completion, and final PGN rebuilding removes an interrupted orphan. Resume requires unchanged manifest. A malformed partial JSON record raises instead of being silently ignored; no resume occurred in the audited snapshot.
- The primary bootstrap's multinomial counts are mathematically equivalent to independent resampling of game scores within each policy color. Averaging the two color samples at equal weight matches the design. Transforming percentile score endpoints with monotone `400 log10(s/(1-s))` correctly yields relative match Elo endpoints. It does not calibrate human Elo. One predeclared comparison avoids an unreported multiple-comparison selection.
- Cap sensitivity correctly bounds all capped draws as p95 wins or losses and separately reports score excluding caps. Final verifier checks all target counts, color balance, IDs/seeds, every legal move, earliest app endpoint, final FEN, hashes, result/score, PGN/mainline/header agreement and source manifests.

The auxiliary pooled decisive-game binomial p-value is not the primary color-stratified analysis. It assumes exchangeable decisive outcomes under a simple 50/50 null; color effects and different draw probabilities can make that a weaker assumption than the primary stratified bootstrap. Use the predeclared score/Elo interval for the main inference.

Independent first-100 replay passed: 100 unique IDs, 200 distinct seeds, 8,630 legal plies, zero continuation after app terminal, and no result/termination/score/FEN/hash/PGN mismatches. The snapshot selects ascending game number then shard: 17 games each from shards 0–3 and 16 each from shards 4–5. Its 52/48 color split is only an audit sample; no interim score or Elo is estimated. See [first100-audit.json](first100-audit.json) and [audit_game_snapshot.py](audit_game_snapshot.py). The six immutable manifests and snapshot hashes are archived there.

The independent full primary replay subsequently passed all 1,200 games and PGNs, 107,794 plies, 2,400 unique seeds and 600/600 policy-color balance. Every source/model manifest, ID/seed schedule, legal move, earliest app endpoint, result, score, final FEN, movetext hash and PGN agrees. All complete sequences are distinct; no game reaches the 400-ply cap. Reconstructing W/D/L and the 200,000-replicate color-stratified bootstrap from raw rows exactly matches 671/100/429, score 0.6008333333 and relative match Elo +71.0399 [52.2154, 90.2854]. See [final-audit.json](final-audit.json).

The optional paired claim-sensitive prefix audit also passed all 1,200 stored games and PGNs. Independent replay finds each earliest `python-chess outcome(claim_draw=True)` endpoint and confirms the exact stored prefixes, 69 truncated games, 29 changed results and 1,556 removed plies. Independently reconstructed sensitivity W/D/L is 654/129/417, score 0.59875 and relative match Elo +69.5322 [50.7357, 88.4307], with zero caps. These correlated prefixes are analyzed separately from the primary games.

This inference-free audit does not substitute for selected original-seed model replay by the strength worker. Confidence intervals remain conditional on this model, implementation, app draw rules, starting position and sampling design.
